# Проверка уточнений и изменения 3.7.1

Дата: 20.08.2026. Базовая выборка остаётся замороженной: 767 уникальных `game_id`, 761 завершённая партия. Веса карт, positional evaluation и калибратор по этой выборке не изменялись.

## 1. Shared deck после cooldown

Точная серверная позиция карты в lower half не восстановлена и не моделируется. Реализация является явно обозначенной empirical approximation:

1. Для каждой публично сыгранной или сброшенной карты хранится `last_seen_action`.
2. При `age < 45` вес карты строго равен нулю.
3. Начиная с `age=45`, используется не равномерный возврат, а кусочно-линейный age-weight по эмпирической CDF 1 673 точных повторных доборов:

   - 44 → 0%;
   - 45 → 6%;
   - 46 → 12%;
   - 48 → 24%;
   - 50 → 34%;
   - 55 → 53%;
   - 60 → 67%;
   - 65 → 77%;
   - 70 → 84%;
   - 78 → 90%;
   - 100 → 97%;
   - 139 → 100%.

4. Между узлами вес интерполируется линейно.
5. Текущая наша рука исключается из скрытой руки соперника.
6. Шестикарточная рука частицы выбирается weighted sampling without replacement.

Это не симулятор точной очереди общей колоды: архив доказывает cooldown и распределение возраста повторного появления, но не доказывает серверный алгоритм помещения карты в конкретную позицию lower half.

## 2. Reconnect с пропущенными действиями

3.7.0 сохранял известную историю, но не моделировал несколько полностью пропущенных действий между старым belief и новым `turn`. В 3.7.1 это исправлено:

1. После загрузки persisted state всегда повторно сканируются все доступные сегменты того же `game_id`.
2. Известные события из сегментов replay по серверному action index; terminal polling artifact удаляется.
3. При скачке, например, `11 → 15`, и известном хвостовом `DISCARD` на 15 действия 12–14 записываются как неизвестные latent transitions.
4. Хвостовой PLAY/DISCARD на 15 применяется точно.
5. В каждой частице latent действия 12–14 независимо пересэмплируются в хронологическом порядке из совместимого weighted pool.
6. Выбранная в latent PLAY/DISCARD карта получает cooldown на соответствующем action index до выборки текущей скрытой руки.
7. Неизвестные indices и известная история сохраняются на диск и переживают следующий reconnect.

Regression test: `test_reconnect_turn_jump_resamples_missing_play_discard_transitions`. Он создаёт известное действие 11, имитирует потерю связи во время действий 12–14, возвращает состояние с `turn=15` и хвостовым `d92-4`, проверяет точную запись карты 92, наличие трёх latent transitions, particle resampling, несовместимость пересэмплированной карты с текущей скрытой рукой и повторную загрузку состояния с диска.

Ограничение остаётся принципиальным: если сервер после reconnect сообщает только последний ход, точные карты действий 12–14 восстановить невозможно. Поэтому они не «угадываются как факт», а интегрируются как uncertainty внутри belief.

## 3. Particle range и 80 частиц

`200–1200` — нормальный adaptive range при достаточном времени. При `time_left=6`:

- safety margin оставляет около 2 секунд анализа;
- размер пачки уменьшается с 200 до 40;
- в контрольном replay успели полностью завершиться две пачки, то есть 80 общих частиц для всех кандидатов;
- предиктор времени определил, что следующая пачка не поместится до hard stop;
- вернулся последний полностью рассчитанный ranking.

Это deadline degradation, а не утверждение, что нормальный статистический минимум равен 80.

Новые поля каждого кандидата и выбранного решения:

- `particles_requested` — число частиц в запущенных batch requests, включая незавершённую пачку;
- `particles_completed` — число частиц, полностью рассчитанных для всех кандидатов;
- `stopping_reason` — `statistical_convergence`, `max_particles`, `deadline_precheck`, `deadline_in_batch`, `terminal_or_single_choice` либо `emergency_fallback`;
- `deadline_remaining` — оставшийся wall-clock запас до внутреннего analysis deadline;
- `decision_margin` — разность P(win) top-1/top-2;
- `se_diff` — paired standard error разности на common random numbers;
- `ci_diff` — двусторонний 95% confidence interval разности;
- старые `particle_count` и `confidence_interval_pp` сохранены для совместимости, причём `particle_count == particles_completed`.

## 4. Полностью out-of-sample серия

Новая серия помечается `strategy.version=3.7.1-cyclic-resync-adaptive` и `oos_series_id=3.7.1-2026-08-20`. Старая выборка не используется для изменения весов.

Сравнение выполняет `tools/compare_oos_card_versions.py`:

- группирует reconnect-сегменты по `game_id`;
- отбрасывает terminal polling duplicates;
- фильтрует candidate только по точной версии 3.7.1;
- аварийно завершает анализ при любом пересечении candidate `game_id` со старым baseline;
- требует по умолчанию минимум 100 новых завершённых игр;
- сравнивает win rate с Wilson 95% CI;
- Brier и ECE с 300-повторным block bootstrap по целым `game_id`;
- долю `DECISION UNCERTAIN`;
- deadline failures и незавершённые batch requests;
- наличие resync metadata, количество reconnect gaps и пересэмплированных latent actions;
- отдельно показывает результат при первом ходе нашего AI и соперника.

Результата новой серии сейчас ещё нет: реальные партии должны физически пройти на версии 3.7.1 после 20.08.2026. Подмена их replay старого архива нарушила бы требование out-of-sample.
